# 附件

截图、照片、PDF 这类和事项放在一起的文件。

- 每个附件属于一个事项，或一条还没整理完的 [AI 整理](../ai.md#附件)请求，有名称、类型和大小，单个不超过 20 MB，同一项里按添加的先后排列。
- 添加：详情里的“添加附件”（手机上可以拍照、选相册或文件），在详情、描述编辑框或快速添加栏里粘贴，电脑上拖进来，见[界面](../ui/attachments.md)。
- 名称：选的和拖进来的文件用原来的文件名。粘贴的图片，和系统起的看不出内容的名字（`image.png`、`IMG_20261117_093212.jpg`、`Screenshot_2026-11-17-09-32-12-345_com.tencent.mm.jpg` 这类只有固定前缀、数字和日期的）一样，改叫“图片 1.png”“图片 2.jpg”：同一项里下一个没用过的号，扩展名不变。只认这几种固定的写法，不去猜别的名字。名称可以改，最长 200 字，不能含 `/` 和 `\`，也不能是 `.` 或 `..`；存到电脑或手机上时，系统不允许的字符换成 `_`，太长的截短。
- 引用：描述里可以引用附件，写成 Markdown 链接 `[名称](attachment:<附件 ID>)`，名称里的 `[`、`]`、`\` 前面加 `\`。预览时它是一个小标签：图标加附件现在的名称（改了名也跟着变），点开就是这个附件。只认这个事项自己的附件：附件已删除，或者 ID 是别处的，标签变灰，写引用里的名称。在描述编辑框里粘贴或拖进文件，加为附件的同时在光标处插入引用；附件的菜单里也有“在描述中引用”。
- 删除附件可以撤销，撤销的不必是上传的人；删除事项、文件夹或 AI 整理请求时，它们的附件一起删除，撤销时一起回来。谁看得到事项，谁就看得到它的附件：事项移进、移出共享的文件夹时附件跟着走，新看到的人收到它，看不到了的人那里它被删除。
- 压缩图片：上传前在设备上把 JPEG 照片重新编码（质量 0.85），长边超过 2560 像素的缩到 2560。手机照片从 3–8 MB 降到 0.5 MB 左右，拍摄地点等 EXIF 信息也随之去掉。PNG 截图和其他格式原样上传。默认压缩，管理员可以在设置里改为一律上传原图，见[设置](../ui/settings.md)。
- 同步：附件的名称、类型、大小和属于哪一项，和其他数据一样走[改动](../design.md#改动)，离线时也能添加、改名和删除，可以撤销。文件本身单独上传：先存在设备上、立即显示，联网后在后台上传；上传完，加附件的改动才发给服务端，所以服务器上有的附件一定有文件。上传被服务器明确拒绝时（如超过反向代理允许的大小），这个附件和一个被拒绝的改动一样撤回，并提示原因。别的设备第一次显示时才下载，下载过的存在设备上，离线也能看。见[网页端](../web.md#附件)。
- 存储：服务端把文件存在数据目录的 `files/` 里，数据库只存附件的信息，每天的快照不会把文件复制 7 份。删除的附件，文件再留 90 天（和改动记录一样），这期间撤销还找得回来。存文件只经过服务端的一个模块（`crates/server/src/files.rs`），按 ID 写入、读出和删除，以后改存到 S3 这类对象存储只换这一层。
- AI 整理可以把图片一起发给能识别图片的模型，见 [AI 整理](../ai.md#附件)。
