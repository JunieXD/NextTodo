# NextTodo 总体设计

这里写整体的设计和各处共用的规则；下面这些另有单独的一篇：[开始、截止和提醒](design/dates.md)、[重复、农历和放假](design/repeat.md)、[附件](design/attachments.md)、[共享](design/sharing.md)、[改动记录和撤销](design/history.md)、[App 更新](design/updates.md)。

## 定位

待办应用，核心是事项之间的先后关系：事项和依赖组成一张有向无环图，首页随时列出“现在能做的事”。文件夹可以无限嵌套，用来分开不同的项目。手机优先，网页、Android、iOS、macOS、Windows 实时同步，离线也能用。agent 通过 API、命令行和 MCP 管理整个待办。支持多个账号，朋友凭邀请码注册；文件夹可以共享给同一台服务器上的其他人，几个人分工做一个项目，见[共享](design/sharing.md)。不想部署服务器的，App 可以只在本机使用，见[本机模式](local.md)。

## 概念和规则

### 文件夹

- 可以无限嵌套，也可以没有文件夹，事项直接放在根目录。默认不建任何文件夹。
- 同一层的文件夹不能重名，名字里不能有 `/`，所以每个文件夹都能用路径（如 `/工作/网站改版`）唯一指明。
- 同一层的文件夹按手动顺序排列。
- 删除文件夹会连同里面的子文件夹和事项一起删除：界面上先确认，删除后能撤销。
- 文件夹可以选颜色和图标，一眼认出是哪个：颜色有 14 种预设，也可以自己调；图标是 40 个预设，见[界面](ui.md#文件夹的颜色和图标)。只用在文件夹的图标上，不染别处。没选的照旧。随文件夹同步，共享的文件夹里大家看到的一样；共享的文件夹本身的颜色和图标只有共享人能改（见[共享](design/sharing.md)）。
- 复制文件夹会连同里面的子文件夹、事项、附件，以及它们之间的先后关系，一起复制一份，用来把一套流程当模板反复用，比如签合同要走的审价、盖章、法人签字。
  - 副本里的事项都是待办：完成过的变回待办，重复的事项完成次数清零。开始、截止、提醒和重复原样保留。连到文件夹外面的依赖不复制。
  - 颜色和图标一起复制。
  - 副本放在原文件夹的同一层，名字用原名，同一层已有就叫“签合同 副本”，再有就是“签合同 副本 2”……；原名太长时截短，留出“ 副本”的位置，不超过名称的 100 个字。别人共享给我的文件夹复制到我的根目录。
  - 附件的文件另存一份，描述里对这些附件的引用改指副本里的附件。
  - 负责人：副本还在同一个共享的文件夹里的保留，否则去掉。共享的文件夹复制出来的副本不共享。
  - 一次复制是一个批次，能撤销；最多 1000 个操作（文件夹、事项、依赖和附件各算一个）。

### 事项

| 字段 | 说明 |
|---|---|
| 编号 | 每个用户从 1 开始递增的短编号（如 `#42`），由服务端在收到时分配，方便命令行和 agent 引用。离线新建的事项同步后才有编号。共享的文件夹里的事项用共享人的编号，见[共享](design/sharing.md) |
| 标题 | 必填，单行 |
| 描述 | 可选，Markdown（GFM，支持 `- [ ]` 清单），可以引用附件 |
| 附件 | 可选，截图、照片和其他文件，见[附件](design/attachments.md) |
| 文件夹 | 可选，不填就放在根目录 |
| 负责人 | 可选，可以有多个，只有[共享](design/sharing.md)的文件夹里的事项能设；没设时所有成员都能做 |
| 完成时间 | 为空表示待办，有值表示结束了：做完了，或者[放弃](#放弃)了（另记一个“放弃”）。状态只由这两个字段决定。默认是勾选的时候，可以改成实际做完的时候，见[完成时间](#完成时间) |
| 截止时间 | 可选：一个日期，可以再加具体时间（精确到分钟）；也可以是“前置完成后几天内”，见[前置完成后的截止](design/dates.md#前置完成后的截止) |
| 提醒 | 可选，可以有多个：按截止时间、开始时间算，或在指定的某天几点，见[提醒](design/dates.md#提醒) |
| 重复 | 可选，只有设了截止时间才能设：每 N 天、每 N 周、每 N 个月或每 N 年，按周的可以选周几，按月的可以选几号，可以设重复到哪天，见[重复](design/repeat.md#重复) |
| 顺序 | 手动顺序，作为依赖顺序之外的次级排序 |

### 依赖

- `A → B` 表示 A 完成后才能做 B，A 是 B 的**前置**，B 是 A 的**后续**。
- 可以跨文件夹连，但只能连在同一处：私人的事项之间（不在任何[共享](design/sharing.md)的文件夹里），或同一个共享的文件夹里的事项之间。在同一处移动事项时依赖不变。
- 不能成环：服务端在每次加依赖时检查，成环就拒绝，并返回环上的事项。
- 删除事项时，连着它的依赖一起删除。

### 派生状态

| 状态 | 条件 |
|---|---|
| 可做 | 待办，所有前置都已完成或放弃，并且到了[开始时间](design/dates.md#开始时间)（没设的不用等）。[重复](design/repeat.md#重复)的前置做过这一次就算完成 |
| 等待中 | 待办，还有前置没结束，或者还没到开始时间 |
| 已完成 | 有完成时间，没有放弃 |
| 已放弃 | 有完成时间，标为放弃 |

前置没完成也能直接把事项标为完成（现实里经常有跳步），界面上会先确认一次。重新打开一个已完成的事项，它的后续可能因此变回“等待中”。

### 放弃

没做成、以后也不做了的事项标为“放弃”。和删除不同：删除给加错了、本不该有的事项用；放弃的留着，看得到当初有这件事、什么时候放弃的。

- 和完成一样算结束：不在“接下来”、小组件和提醒里，不再逾期。在[已完成](#已完成)里和完成的放在一起，标“已放弃”；点勾选圈同样恢复成待办。
- 放弃的前置不再挡着后续：这一步不用等了。还有没结束的后续时，确认框问“只放弃这一项”还是“连同 3 项后续一起放弃”（后续的后续也算，已经结束的和隔着它的不算），一个改动，撤销时一起回来。
- 重复的事项放弃就是整个结束，不再有下一次；只是这次不做，用[跳过](design/repeat.md#重复)。
- [关联进度](#关联进度)照常算它一步。[日历](#日历)里照常列在截止那天，样子是放弃的；热力图只数完成的。
- 前置还没结束也能直接放弃，不用确认：放弃不会让谁误以为前面做完了。
- agent 用工具 `drop`，命令行 `nexttodo drop`；事项的 `status` 多一种 `dropped`，见 [agent 接入](agent.md#工具)。

### 完成时间

- 勾选时记下当时的时间。忘了勾、过后才勾的（组会那天没勾，第二天才想起来），可以把完成时间改成实际做完的时候：[日历](#日历)和“已完成”的分组、先后都按改过的算。放弃的同样可以改放弃的时间。
- 不能晚于现在。改它不影响先后关系（后续本来就已经可做），是一次普通的改动，记进[改动记录](design/history.md)，可以撤销。
- [重复](design/repeat.md#重复)的事项没有完成时间，改的是完成记录里完成的那天。改的是修改前最晚做完的那次、事项还在重复、下一次从完成那天算的，截止（连同开始）换成从新的日子算出的下一次；算出下一次超过“重复到”的日期时结束重复，截止改为这条记录的截止日期，开始随之平移，完成时间为现在。改其他记录不重算下一次。修改后，最近完成日期取所有记录里最晚的完成日；完成日相同时，先比较截止日期，再比较同一次完成的回数。做完最后一次后，从详情改结束时间或改那次完成记录时，两处的日期一起更新。
- 完成时也能直接指定：agent 的 [`done --at`](agent.md#工具) 可以带钟点；[AI 整理](ai.md#整理文件夹)只补记日期（“组会昨天就开完了”“记一下昨天开了组会”）。
- 在哪里改见[详情](ui/dialogs.md)。

### 关联进度

经前置、后续连在一起的事项，可做时在“接下来”、小组件和 `next` 工具里标出它是第几步、共几步，如“2/5”。按先后关系数步数：

- 第几步：这一项前面最长的一串前置有几项，再加一。同时能做的几项是同一步。
- 共几步：经过这一项、从头到尾最长的一串有几项。
- 只看连线，不看完成了没有，已完成的也算一步：勾掉一项、跳着做，别的事项的数都不变。连线可以跨文件夹。

| 情况 | 显示 |
|---|---|
| 一条线 A → B → C → D → E | A 是 1/5，B 是 2/5，E 是 5/5 |
| A 之后 B、C 可以同时做，D 等 B 和 C | A 是 1/3；B、C 都是 2/3；D 是 3/3 |
| X、Y、Z 都做完才能做 D，D 之后是 E | X、Y、Z 都是 1/3；D 是 2/3；E 是 3/3 |
| 两件事共用一个前置：“开通账号”之后，甲有 2 步，乙有 3 步 | 甲的是 2/3、3/3，乙的是 2/4、3/4、4/4；“开通账号”本身是 1/4 |
| 长短两条线汇到一项：P → Q → R → T，还有 S → T | S 是 1/2，T 是 4/4，按长的那条 |

- 没有前置、后续的事项不标。只标在可做的事项上：文件夹页有轨道画出先后，不标。
- 网页离线时也要显示，所以和依赖状态一样，核心库（Rust）和网页端（TypeScript）各算一份，用同一套测试数据校验。

### 排序

- 文件夹内：待办事项按依赖排，有先后关系的挨在一起：后续紧跟在它的前置后面（有几个前置的，跟在排得最后的那个后面），后续的后续再接在它后面，一串排完再排下一项。同一个前置后面的几个后续之间、没有前置的事项之间，按手动顺序排。先后约束也算经过文件夹外未完成事项的间接依赖（A → 外面的 X → B，B 照样跟在 A 后面）；中间的事项已经完成时，这条路径不再约束。已完成的折叠在底部，最近完成的在前；设置里可以让最近完成的几项划掉后留在原处，不折叠（默认不留，见[设置](ui/settings.md)）。
- 手动拖动排序只在同一层里换顺序：没有前置的事项在它们之间，同一个前置的几个后续在那个前置后面的一段里；拖动的事项后面那一串跟着它走。有几个前置的后续照旧跟在排得最后的那个后面，拖动以后可能改跟另一个。拖出这个范围时弹回并提示原因。
- “接下来”：只列“可做”的事项。有[要赶的截止](design/dates.md#后续的截止)的（自己的截止，或者后续更早的截止）按时间从早到晚排在前面（只有日期的算当天最晚），其余按所在文件夹的顺序和手动顺序排。文件夹的顺序是从根目录开始把文件夹树从上往下展开，父文件夹在子文件夹前面；共享给我的文件夹排在自己的后面，按“共享给我”一组的顺序。

## 界面

### 布局

| | 手机 | 电脑（宽屏） |
|---|---|---|
| 导航 | 底部栏：接下来、日历、文件夹、设置 | 左栏：接下来、已完成、日历、文件夹树（根目录在最上面）、共享给我、搜索，设置在左下角。左栏可以收起 |
| 内容 | 文件夹逐层点进去，标题栏可切换列表和关系图 | 中栏显示列表或关系图 |
| 详情 | 底部面板，可以上拉展开、下拉关闭 | 右栏，打开事项时滑出，关掉时收回 |

### 接下来

首页。列出[我的事项](design/sharing.md)里所有“可做”的，每项显示所在文件夹路径、截止时间和[关联进度](#关联进度)，已逾期的标红。还没到[开始时间](design/dates.md#开始时间)的不在这里，到了自动出现。Android 小组件显示的也是这份列表。

- 按[要赶的截止](design/dates.md#后续的截止)分组：已逾期、今天、7 天内、以后、无截止时间，空的组不显示。组标题点一下收起，再点展开；收起时标题后面写几项。收起哪些组记在这台设备上，每个账号一份。
- 有后续的事项可以就地展开后面的一串事项，看做完它通向哪里、哪一步另有前置，见[界面](ui/next.md#接下来里的后续)。
- 做完的[重复](design/repeat.md#重复)事项带着下一次的截止留在这里，不想提前看到的设[开始时间](design/dates.md#开始时间)，可以按截止往前数几天；第一次遇到时有提示，见[开始时间](design/dates.md#开始时间)。
- 可以只看某些文件夹：选一个、几个或全部（默认），选了一个文件夹就包括它的子文件夹。用来分开场景，比如电脑上只看“工作”。见[界面](ui/next.md#接下来的文件夹筛选)。
- 选择存在各自的设备上，和主题一样；小组件和菜单栏小窗跟着这台设备的选择。提醒不受影响，照常提醒所有事项。
- agent 的 `next` 用 `folders` 参数做同样的筛选，见 [agent 接入](agent.md#工具)。

### 已完成

所有文件夹里完成和[放弃](#放弃)的[我的事项](design/sharing.md)，最近结束的在前，按结束的日期分组，每项显示所在文件夹，放弃的标“已放弃”。点勾选圈就恢复成待办，不小心勾掉、又不记得在哪个文件夹的事项从这里找回；也可以[批量操作](ui/batch.md)，一次重新打开或删除多项。手机上从“接下来”页右上角进入，电脑上在左栏。

### 日历

按日期看事项：哪天要做什么，过去每天做了多少。手机上是底部栏的第二项，电脑上在左栏“已完成”下面。

- 上面是月历，可以切换成一周或全年：
  - 月：周一开始、固定 6 行，每天的数字下面写[农历](design/repeat.md#农历)，或者[节日、节气](design/repeat.md#节日和放假)，放假和补班的日子另有标记。也可以在格子里写事项的标题，看得更细，见[界面](ui/calendar.md)。那天截止、还没结束的[我的事项](design/sharing.md)用小圆点表示（最多 3 个），重复事项以后的每一次也算；过去的日子按那天完成了几项涂上深浅不同的主色（热力图）。
  - 周：只显示选中那天所在的一周，格子同月历，下面的列表多出地方。
  - 年：一年 12 个月的热力图，每月一个小月历，一天一格，颜色深浅同上；点一天回到月历的那一天。
  - 时间轴：按钟点排的一周，像日程表，看一周里什么时候要交什么。有具体时间的事项画在截止的钟点，只有日期的在顶上的“全天”一行；点空白处往那个钟点添加。事项没有时长，开始时间说的是“之前不能做”，也不当成时长画。默认显示，不需要的可以在设置的“外观”里关掉。见[界面](ui/calendar.md)。
- 下面是选中那天的事项：
  - 选中今天时，最前面是已逾期的：截止在今天以前、还没完成的，同[日程小组件](android/widgets.md#日程)和 `agenda`。
  - 截止在那天的：现在这一次截止在那天的照常显示，可以勾，逾期的标红；重复事项以后的某一次落在那天的写“以后的一次”，不能勾，点开是这个事项。
  - 那天完成的：普通事项按完成时间在这台设备上是哪天，重复事项按[完成记录](design/repeat.md#重复)。做完最后一次而完成的重复事项只列一次，算在那次记录的那天。数据里分不出是做完最后一次、还是结束重复并完成的：结束重复并完成时截止日期正好有完成记录的（按完成那天算的提前完成过，下一次还是同一天截止），也算在那条记录的那天。
- 可以往选中的那天添加事项：截止就是那天，带上默认提醒。
- 完成了几项：那天列出的完成的事项和完成记录一共几项。热力图分 4 档：1 项、2–3 项、4–6 项、7 项及以上。
- 都在设备上算，离线也能看。以后的每一次按重复的规则从现在的截止日期往后推，推到看的那个月为止，设了重复到的到那天为止；“从完成那天算”的按每次都在截止那天完成来推。和[排序](#排序)一样，核心库和网页端各算一份，用同一套测试数据校验。
- Android 另有[日程小组件](android/widgets.md#日程)，列出今天起 7 天的；agent 用 [`agenda`](agent.md#工具) 看同样的内容。

### 文件夹

- 根目录和文件夹一样：有子文件夹（就是顶层的文件夹）、事项、已完成区和快速添加。手机上“文件夹”页就是根目录，总是列表，带全部事项的搜索；电脑上左栏的文件夹树以根目录为顶层。别人共享给我的文件夹在手机“文件夹”页和电脑左栏都单独一组“共享给我”。
- 先列子文件夹，再列事项。左侧用“轨道”画出事项之间的先后关系。等待中的事项显示为灰色，并标注“等 N 项”。
- 右滑完成，左滑删除或进入更多操作，长按拖动排序，或拖进别的文件夹（电脑上也能拖到左栏的文件夹树上），见[拖动](ui/drag.md)。
- “…”菜单里的“批量操作”一次选中多项，完成、串起来（按列出的顺序连成一串）、移动或删除，一步就能撤销，见[批量操作](ui/batch.md)。
- 底部有快速添加栏。
- 共享的文件夹：标题旁是成员的头像，点开共享面板；有负责人的事项右侧是负责人的头像。见[界面](ui/sharing.md)。

### 关系图

- 显示当前文件夹（可选包含子文件夹）里的事项和依赖。连到文件夹外的依赖显示为半透明节点，标注所在文件夹。
- 有快速添加栏，同列表：新加的事项出现在图里，闪一下，可以接着加或连线。
- 布局全自动，用 ELK 分层布局：手机上从上到下，电脑上从左到右。连线不穿过节点，交叉尽量少，链条尽量直，可做的事项排在第一层。不保存节点位置。
- 可以平移和缩放：手机上单指拖动、双指捏合，电脑上用触控板或鼠标。
- 冗余连线默认不画：已有 A→B→C 时就不画 A→C，但数据里保留。
- 已完成的事项默认隐藏，可以切换显示。
- 选中一个节点时，高亮它的全部前置链和后续链。
- 编辑：
  - 点“连线”进入连线状态，依次点前置和后续两个节点建立依赖，可以接着连下一条，点“完成”退出；点连线弹出删除确认；点节点打开详情。电脑和手机相同。

### 详情

标题、完成勾选、所在文件夹（点了移动，旁边的按钮跳到那个文件夹，见[在文件夹中显示](ui.md#交互细节)）、负责人（共享的文件夹里）、截止时间（含重复；没完成的后面写还有多久或逾期多久，见[界面](ui/dialogs.md)）、提醒、重复的事项完成过几次、“跳过这一次”和“结束重复并完成”、[放弃](#放弃)、描述（编辑和预览切换）、[附件](design/attachments.md)、前置和后续列表（可以搜索添加、单独移除），底部显示创建和最后修改的来源（本人、别的成员，或谁的哪个令牌）。

点标题就地编辑，光标落在点的位置（用键盘打开的在末尾）；回车或点别处保存，Esc 放弃。正在编辑时关掉详情（下拉、返回键、换成别的事项），标题和描述也会保存。

编辑标题或描述时，它在别处（agent、另一台设备）被改了的话，保存时弹窗说明谁改的、显示对方的版本，让用户选“保留对方的”或“用我的覆盖”。关掉弹窗按覆盖处理：覆盖后提示条上可以撤销，放弃的修改却找不回来。

### 搜索

按标题和描述搜索看得到的全部事项（包括共享给我的文件夹里的），结果显示文件夹路径。

### 设置

单独的页面，按管的是什么分类别，每类一个子页：账号（本机模式下是备份和恢复）、改动记录、[隐私锁](#隐私锁)（网页和桌面）、外观、列表和添加、提醒、小组件（Android）、系统（Android 和桌面）、AI 整理、agent 接入（令牌和命令行）、服务器（仅管理员：升级、邀请注册、附件；本机模式下只有附件）、关于。见[界面](ui/settings.md)。

### 隐私锁

公司的电脑有时别人会用：离开一会儿，坐过来的人不该看到我的事项；回来时解锁要快。

- 网页和桌面 App 上有，本机模式也有；手机有系统的锁屏，不做。在设置“隐私锁”里打开：设 4 到 6 位数字的 PIN，同时得到一个恢复码。只在这台设备上生效（网页是这个浏览器），不同步。
- **什么时候锁**：这台设备上的 NextTodo（网页的所有标签页，桌面的主窗口和菜单栏小窗）闲置到设定的时间就锁定，可选 1、5、15、30 分钟，默认 5 分钟。闲置是这么久没有在它上面按键、移动或点按鼠标、触摸，窗口在后台、电脑睡着了都算。所以关掉页面或 App 隔久了再打开，也是锁着的。也可以立即锁定：设置里的“立即锁定”，桌面 App 的菜单栏或托盘图标菜单里的“锁定”。
- **锁定时**：所有窗口和标签页只显示锁屏，刷新也不解开。正在编辑的标题和描述先保存。同步和提醒照常，提醒和每日汇总的通知只写“有事项提醒”，同[隐藏通知内容](design/dates.md#提醒)。没登录时没有锁：登录页上没有事项，登录后也不再要 PIN。
- **解锁**：输入 PIN，所有窗口和标签页一起解锁。连错 5 次以后不能再输 PIN，要用恢复码，连服务器时也可以用账号密码；忘了 PIN 也这样解锁，解锁后要设一个新的 PIN。恢复码只在生成时显示一次，设置里可以换一个新的，旧的随即失效。两样都没有了的，按官网的[隐私锁](https://juniexd.github.io/NextTodo/guide/basics#lock)清掉这台设备上的网页数据，锁就去掉了：已经同步到服务器、写进本机模式服务端的数据不受影响，还没同步的改动和快速添加的草稿会一起清掉，官网写明了先联网同步。
- 这是防止别人看见，不是加密：数据还在这台设备上，懂行的人能绕过它。设置里写明这一点。
- PIN 和恢复码只存[慢哈希](#哈希用途)：很多人的 PIN 和银行卡的一样，存原文的话，翻看浏览器存储的人就看到了。
- 网页[经 HTTP 打开](web.md#经-http-打开)时没有隐私锁：算哈希的浏览器接口只在安全上下文（HTTPS 和 `localhost`）里有。

## agent 接入

所有入口都走同一条改动管线（见[同步](#同步)），agent 做的改动会实时出现在所有设备上。

### 令牌

在设置里生成，自己起名（如“Claude Code”），分只读和读写两种。令牌只在生成时显示一次，同时给出填好服务器地址和令牌的接入写法，点一下就复制：Claude Code 和 Codex 的 MCP 配置、命令行的环境变量（macOS、Linux 和 Windows 两种写法），以及安装 skill 的命令。改动记录里用令牌名标明来源。

### 命令行、MCP 和工具接口

服务端实现一组工具（查询树、列表、接下来、详情、搜索、关系图、改动记录、读附件，增删改事项和文件夹，加减依赖和附件，批量应用，撤销），命令行 `nexttodo`、MCP 端点 `/mcp` 和 HTTP 工具接口调用的是同一份实现，参数、行为和输出一致。命令行是 Rust 写的单文件二进制，只负责收发，启动只需几毫秒。默认输出简洁的中文文本，加 `--json` 输出结构化数据。

批量应用的输入是一份计划：新事项用临时的 `ref` 互相引用，已有事项用编号引用，全部成功或全部不生效，可以先预览：

```yaml
folder: /工作/网站改版
tasks:
  - ref: design
    title: 出设计稿
    due: 2026-11-20 18:00
  - ref: api
    title: 写接口
  - title: 联调
    after: [design, api, 42]
```

工具清单、参数、输出格式和各客户端的配置见 [agent 接入](agent.md)。

### Skill

仓库里的 `skills/nexttodo/` 告诉 agent 下面这些。命令行带着同一版本的一份，`nexttodo skill install` 装到 Claude Code、Codex 等 agent 的 skill 目录；只接 MCP 的 agent 在连接时收到它的要点。

- 什么时候用 NextTodo、用命令行还是 MCP；
- 怎么把一个目标拆成有依赖的事项：标题写成动作，描述写清完成标准，只连真正的先后关系；
- 批量改动前先预览给用户看；
- 回答“现在该做什么”时用 `next`。

## 账号

- 用户名加密码登录，密码用 Argon2id 存储。
- 第一个管理员在服务器上用命令行创建。其他人注册需要邀请码，邀请码由管理员生成，每个只能用一次。
- 登录后每台设备得到一个会话令牌：网页存在 HttpOnly Cookie 里，App 存在 App 私有的存储里（Android 是 SharedPreferences，小组件也要读；iOS 是 UserDefaults；桌面 App 是 WebView 的 `localStorage`），没有另外加密。设置里可以看到并注销各设备。
- 每个用户只能读写自己的数据和共享给自己的文件夹。所有表都带 `owner_id`，另有一张成员表记录谁是哪个共享的文件夹的成员；服务端在每个查询上按“自己的，加上自己是成员的文件夹里的”过滤。现有数据不用改。

## 同步

### 原则

服务端是唯一的权威数据源。客户端在本地保存一份完整副本，所有操作先在本地生效，再在后台同步。本机模式[借网盘同步](local/drive.md)时，先后由网盘里编号连续的改动排定，各设备上的服务端按这个顺序写入。

### 改动

- 客户端的每个操作是一个“改动”：带客户端生成的唯一 ID（UUIDv7），内容是操作类型和参数，比如新建事项、修改字段、移动、加依赖。新建的实体也由客户端生成 UUIDv7 作为 ID，离线时就能互相引用。
- 修改只发送改了的字段。服务端按收到的顺序应用，同一字段以后到的为准。离线时改的字段联网后同样以后到的为准，会盖过期间别处对同一字段的修改；盖掉的值留在改动记录里，可以用命令行或 agent 的 `log`、`undo` 找回。在线时的同时修改见[详情](#详情)和 [agent 接入](agent.md#同时修改)。
- 服务端在事务里应用每个改动：校验，写入数据，追加到改动日志，然后确认或拒绝。改动 ID 重复时直接返回原来的结果，所以断线重发不会重复生效。
- 改动日志有全局递增的序号，记录实体在改动前后的值，用于增量同步和撤销。日志保留 90 天。

### 连接

- 客户端和服务端保持一条 WebSocket 连接，改动的提交、确认、拒绝和推送都走这一条连接。
- 建立连接时，客户端报告自己已有的最新序号，服务端补发之后的改动；超出保留期就让客户端重新下载完整数据。
- 服务端应用一个改动后，推送给看得到它的每个用户的所有连接，HTTP API 和 MCP 的改动也一样。
- 改动只发给看得到的人：写入时记下这个改动发给谁、各人看到的是什么样子。事项移出共享的文件夹时，留下的成员看到的是它被删除，移进来时看到的是新建。
- 加入、退出或被移出共享的人，设备重新下载一次完整数据。

### 离线

- 没网时，改动存在本地的待发队列（IndexedDB），界面照常更新。联网后按顺序重发。
- 本地看到的状态 = 服务端最新数据 + 待发队列里的改动。服务端确认后从队列移除。
- 被拒绝的改动（如离线时连出的依赖在服务端成环）会撤回本地效果，并告诉用户哪一项、为什么没有生效。

### 传输

- WebSocket 上只传小的增量，不压缩；完整数据走 HTTP，用 brotli 或 zstd 压缩。数据格式用 JSON。
- App 的前端资源打包在安装包里；网页版通过 PWA 缓存资源。之后打开只同步数据。

## 技术栈

| 部分 | 选型 |
|---|---|
| 核心库 `crates/core` | Rust：数据模型、依赖图算法（判环、拓扑排序、派生状态） |
| 服务端 `crates/server` | Rust：axum、tokio、rusqlite（SQLite，WAL 模式）、rmcp（MCP）、argon2 |
| 命令行 `crates/cli` | Rust：clap、ureq（HTTP）、serde-saphyr（读 YAML 计划）、chrono（本机的日期，完成重复的事项时用） |
| Android 本机模式 `crates/android` | Rust：jni，把服务端编译成 App 里的动态库，见[本机模式](local.md#android) |
| iOS 本机模式 `crates/ios` | Rust：把服务端编译成静态库链接进 App，经 C 接口调用，见 [iOS](ios.md#本机模式) |
| 前端 `apps/web` | React、Vite、TypeScript、Tailwind CSS、Radix、React Flow + elkjs、react-markdown + remark-gfm、vite-plugin-pwa、Lucide（图标）；动效用 CSS 动画 |
| Android `apps/android` | Capacitor，小组件用 Kotlin + Jetpack Glance |
| iOS `apps/ios` | Capacitor，原生部分用 Swift |
| 桌面 `apps/desktop` | Tauri 2（macOS、Windows） |
| 官网 `apps/site` | VitePress，发布到 GitHub Pages，见[官网](deploy.md#官网) |
| 类型共享 | ts-rs 从 Rust 类型生成 TypeScript 类型 |

- 前端离线时需要自己计算派生状态和排序，所以这部分算法在 TypeScript 里也实现一份，和 Rust 版用同一套测试数据校验。
- Rust 部分是一个 Cargo workspace，Tauri 的 `src-tauri` 单独一个（免得 `cargo test` 每次都编译 Tauri）；前端部分是一个 pnpm workspace。

### 哈希用途

只用在这几处：密码用 Argon2id；令牌在数据库里存 SHA-256；前端构建产物的文件名带内容哈希（Vite 默认行为，用于长期缓存）；在设置里升级服务端时，按 SHA-256 摘要校验下载的镜像清单和镜像层（OCI 镜像的标准做法，`docker pull` 也这样校验）；[借网盘同步](local/drive.md)用 S3 时，请求按 S3 的规定签名（AWS 签名第 4 版，HMAC-SHA256）；[隐私锁](#隐私锁)的 PIN 和恢复码在本机只存 PBKDF2-HMAC-SHA256 的结果（60 万次，每台设备一个随机的盐，用浏览器的 Web Crypto）。

## 部署

- 服务端是一个进程、一个端口：同时提供 API、WebSocket、MCP 和网页静态文件。静态文件在构建时预先压缩好，放在镜像里，见[网页端](web.md#部署)。
- 自己部署：用 GHCR 上的镜像 `ghcr.io/juniexd/nexttodo`（amd64 和 arm64），`docker compose` 启动，数据在挂载的 `data/` 里；前面一般放一个提供 HTTPS 的反向代理，也可以[直接用 HTTP](#直接用-http)。步骤见[部署](deploy.md)。
- 升级由管理员发起，数据库在新版本启动时自动迁移。为了让管理员知道有新版本，管理员登录的网页和 App 在设置“服务器”里显示服务器的版本（服务器上 `/app/desktop.json` 的 `version`），并向 GitHub 查最新的 Release（`api.github.com`，打开时和之后每天最多一次，进设置“服务器”时不论多久前查过都再查一次，请求里没有用户数据）。已是最新时这一行写“已是最新版本，3 分钟前检查”，查过的结果过时了也看得出来；有新版本时写“可升级到 0.1.N”，旁边是“升级”按钮；同一个新版本在打开时用提示条提醒一次（“服务器可升级到 0.1.N”，附“查看”打开设置“服务器”）。查不到时只在这一行写“无法查询最新版本”。普通用户和本机模式不查。
- 点“升级”并确认（“升级到 0.1.N？服务器将下载约 45 MB，更新时各设备断开几秒；新版本无法启动时自动回退。”）后，服务端自己从 GHCR 下载新版本、换上，起不来时连同数据库一起退回，不经过 Docker，见[部署](deploy.md#在设置里升级)。这一行显示进度：正在下载（百分比）、正在重启，换上后写“已升级到 0.1.N”，网页端随后自动刷新，App 立即检查自己的更新；失败时写明原因，附官网上用命令升级的方法，可以重试。不能这样升级的服务端（开发版、加上这个功能以前的版本），这一行没有按钮，照旧附升级方法的链接。也可以照旧在服务器上用 `docker compose` 换镜像。
- 镜像基于 `scratch`，里面只有静态链接的 Linux 服务端和网页文件（含 [App 更新](design/updates.md)），容器以 65534 用户运行，只监听容器里的 8080。镜像在 Mac 上用 `cargo-zigbuild` 交叉编译后打包，服务器上不编译。
- 镜像里没有可写的临时目录，在设置里升级时新版本又跑在旧镜像里，所以各端自带的 SQLite 编译时就把临时数据（语句日志、临时表和索引、排序）放在内存里（`.cargo/config.toml` 的 `SQLITE_TEMP_STORE=3`）；数据库、WAL 和备份照常写在数据目录。代价是改写整张表的迁移和恢复，内存峰值接近被改写的数据量。
- 反向代理要开启 WebSocket，并把原来的 `Host` 传过去（或设 `X-Forwarded-Host`），网页的同步连接靠它确认是同源页面。
- 服务端启动时和之后每天用 `VACUUM INTO` 做一次数据库快照，放在 `data/snapshots/snapshot-<Unix 秒>.db`，保留最近 7 份。[附件](design/attachments.md)的文件不在快照里，在 `data/files/`，备份时要一起复制。恢复时停掉服务，用服务端的 `restore` 命令换上快照再启动，设备随后重新下载全部数据，见[部署](deploy.md#备份和恢复)。
- 发布：`deploy/build.sh` 构建镜像内容和各端安装包，`deploy/release.sh` 把镜像推到 GHCR、安装包传到 GitHub Releases；`deploy/deploy.sh` 经 ssh 部署到自己的服务器，换版本失败时自动换回上一个。签名密钥从环境变量读取，不进仓库。见[部署](deploy.md#构建发布)。

### 直接用 HTTP

服务端本身只用 HTTP，HTTPS 由反向代理提供。没有证书时（比如只在家里的局域网里用），也可以直接用 HTTP 连它的端口。网页和各个 App 都支持，包括同步、附件和 App 更新，配置见[部署](deploy.md#直接用-http)。

代价是明文传输：途中的人看得到密码、令牌和所有数据，也改得了，包括 Android 热更新的网页部分。APK 和桌面更新包有签名，改不了。所以经公网访问时仍建议用 HTTPS。

- **不写协议的地址**：App 登录页的服务器地址不写协议时，本机和局域网的地址按 `http://`，其余按 `https://`。算本机和局域网的有：
  - 名字：`localhost`、不带点的（如 `nas`），以及 `.local`、`.lan`、`.internal`、`.home.arpa` 结尾的；
  - IPv4：回环 `127/8`、内网 `10/8`、`172.16/12`、`192.168/16`、链路本地 `169.254/16`，以及 Tailscale 这类组网用的 `100.64/10`；
  - IPv6：`::1`、`fc00::/7`、`fe80::/10`。

  不先试 `https://`、失败了再换 `http://`：那样公网上有人挡住 HTTPS 时，App 会悄悄改用明文。写了 `http://` 的照写的连，公网地址也一样。
- **网页**：经 HTTP 打开时不是安全上下文，有几处不同，见[网页端](web.md#经-http-打开)。
- **Android**：
  - 网络安全配置允许明文。
  - 页面来自 `https://localhost`，同步的 `ws://` 和附件的 `http://` 都算混合内容，所以 WebView 允许混合内容（Capacitor 的 `allowMixedContent`）。
- **iOS**：
  - App Transport Security 允许任意地址（`NSAllowsArbitraryLoads`）。
  - 连局域网的地址时，系统会请用户允许访问本地网络（`NSLocalNetworkUsageDescription`）。
- **桌面**：
  - HTTP 插件本来就能发往任意 `http(s)://` 地址。
  - 更新插件允许 `http` 的更新地址（`dangerousInsecureTransportProtocol`），更新包照样校验签名。
  - Windows 的页面本身就是 `http://tauri.localhost`，没有混合内容的问题。
- macOS 和 iOS 的页面（`tauri://localhost`、`capacitor://localhost`）是安全上下文，但 WebKit 不拦它们连局域网的 `ws://` 和 `http://`。2026-11-22 用 macOS 上的 WKWebView 实测过。

## 性能目标

- 打开 App 到看到数据：不超过 300ms（从本地副本读取）。
- 本地操作到界面更新：一帧之内。
- 服务端常驻内存：不超过 30MB。

## 不做

标签、优先级、看板、甘特图、按小时排的日程、评论、子任务（用依赖和描述里的清单代替）。附件不做视频播放、断点续传、在线编辑和每个用户的空间上限。共享只到文件夹为止：不做 @提醒、只读成员、按人分别设权限、跨服务器共享和公开链接。第一版不做网页提醒、桌面小组件和 Linux 桌面 App（Linux 上用网页端）；iOS 和鸿蒙版见 README 的[未来计划](../README.md#未来计划)。
