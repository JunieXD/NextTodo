# 桌面 App

桌面 App 有 macOS 版和 Windows 版：Tauri 2 外壳加载打包在安装包里的网页端，加上菜单栏小窗、桌面小组件、全局快捷键、提醒和开机自启。总体要求见[总体设计](design.md#桌面macos-和-windows)，网页端见[网页端](web.md)，和 [Android](android.md) 共用“App 模式”的连接方式。

## 结构

| 位置 | 内容 |
|---|---|
| `apps/desktop` | Tauri 命令行（`pnpm tauri …`） |
| `apps/desktop/src-tauri` | Rust 外壳：窗口、菜单栏或托盘图标、全局快捷键、提醒、更新。单独的 Cargo 工作区，不进根目录的工作区，免得 `cargo test` 每次都编译 Tauri |

网页端用 `window.__TAURI_INTERNALS__` 判断自己在桌面 App 里，用 User-Agent 区分 macOS 和 Windows。界面和网页一样，只有下面几处不同。

## 连接服务器

也可以不连服务器，在本机使用，见[本机模式](local.md)。

和 Android 相同：登录页多“服务器地址”栏，HTTP 加 `Authorization: Bearer <令牌>`，WebSocket 在 `hello` 里带令牌，设备名是“NextTodo App · macOS”或“NextTodo App · Windows”。

- 页面来自 Tauri 的本地地址，和服务器不同源。HTTP 经 `@tauri-apps/plugin-http` 由 Rust 发出，不受跨域限制，服务端不需要 CORS。
- 令牌和服务器地址用 Capacitor Preferences 存（不在 Capacitor 里时它就是 `localStorage`），和 Android 共用一套代码；桌面没有小组件要读它。
- HTTP 插件关掉了默认的 Cookie：服务端登录时照样设 Cookie，App 不存也不发，只用令牌。
- 页面只有监听事件、开机自启和 HTTP 请求这几项权限（`capabilities/default.json`）。HTTP 请求可以发往任意 `http(s)://` 地址和端口，因为服务器由用户填；范围里不写端口（`https://*`）时插件只放行默认端口。

## 窗口和图标

- 一个主窗口，就是完整的网页端。关窗口只是隐藏，App 留在菜单栏（macOS）或系统托盘（Windows）里继续同步和提醒；菜单里的“退出”才退出，macOS 上 ⌘Q 也可以。
- macOS 的标题栏透明，网页一直画到窗口顶端（`titleBarStyle: "Overlay"`，不显示标题），窗口的三个按钮浮在左栏顶部，和中栏工具条、手机布局顶部栏的按钮在同一条中线上（距窗口顶端 28）；左栏收起时，中栏顶部的按钮让到右边。左栏顶部、中栏的工具条和标题、手机布局的顶部栏可以拖动窗口，双击缩放（`data-tauri-drag-region`）。Windows 用系统标题栏。
- 窗口隐藏后网页照常运行（`backgroundThrottling: "disabled"`）。macOS 的 WebKit 默认在页面隐藏几分钟后挂起它，同步和提醒的交接就停了；这个设置要 macOS 14，所以最低支持 macOS 14。
- 菜单栏或托盘图标：左键点一下弹出[菜单栏小窗](#菜单栏小窗)，再点一下收起；右键菜单有“快速添加”（弹出小窗，输入框获得焦点）、“打开 NextTodo”“锁定”“退出”。“锁定”立即打开[隐私锁](design.md#隐私锁)，没开隐私锁时打开主窗口的隐私锁设置。macOS 用单色模板图，随菜单栏深浅变化；Windows 用 App 图标。
- 全局快捷键：默认不设，用户在设置里自己选一个，见[小窗快捷键](#小窗快捷键)。设了以后在任何应用里按下都能弹出菜单栏小窗，输入框获得焦点；小窗开着时再按收起。
- 要开新窗口的链接（描述里的链接都是）交给系统默认的浏览器或邮件 App，只放行 `http`、`https`、`mailto`。为了接住这类请求，主窗口在 `tauri.conf.json` 里设为 `create: false`，由 Rust 按这份配置创建；小窗也由 Rust 创建。
- 只运行一个实例：Windows 上再次打开 App 时，显示已在运行的那个的窗口（`tauri-plugin-single-instance`）；macOS 本来就这样。

## 菜单栏小窗

常用的几件事不用打开主窗口：看“接下来”、切换文件夹、勾选完成、快速添加。

- 位置和大小：macOS 在菜单栏图标正下方，Windows 在托盘图标上方，放不下时贴着屏幕边缘；宽 360、高 480，圆角，有阴影，深浅跟随[主题](ui/settings.md)。出现在当前的桌面空间里，盖在其他窗口上面。
- 收起：再点图标、按[快捷键](#小窗快捷键)、按 Esc（正在批量选择时先退出选择）、点小窗外面或切到别的应用。收起只是隐藏，下次弹出还是上次的页面。
- 内容从上到下：
  - 顶上一行：左边是视图切换，写“接下来”“日程”“一周”“月历”“时间轴”或当前文件夹的名字，后面一个 ▾；点开是一个菜单，列出“接下来”“日程”“一周”“月历”“时间轴”（设置里关掉时间轴视图时没有）和全部文件夹（按层缩进，共享给我的在后面单独一组），选了就换过去，选择记在本机。右边是“在主窗口打开”按钮，打开主窗口的同一个页面，小窗收起。
  - [快速添加栏](ui.md#其他)，和手机上的一样（✦ 切 AI 整理，在“接下来”里可选目标文件夹，在文件夹里就加到这个文件夹，在日程里加到今天、放进的文件夹同“接下来”，在一周、月历和时间轴里同日历，加到选中的那天或那个钟点）。弹出时输入框获得焦点，回车添加后留在小窗里，可以接着写下一项。
  - 列表：“接下来”和手机上的“接下来”页一样，[文件夹筛选](ui/next.md#接下来的文件夹筛选)和主窗口共用；文件夹和手机上的文件夹页一样（子文件夹、事项和轨道、已完成），点子文件夹进去，视图切换跟着换成它。“日程”按 Android 的[日程小组件](android/widgets.md#日程)分组：今天起 7 天，每天截止的事项，最前面是已逾期的，共用“接下来”的文件夹筛选；桌面端可以勾选，不限项数。“在主窗口打开”打开日历的一周视图，选中今天。“月历”同 Android 的[月历小组件](android/widgets.md#月历)：上面是“2026年11月”和换月的 ‹ ›，下面 6 周的格子铺满窗口，日期和农历写在一行，下面写事项的标题，同日历月视图的[显示标题](ui/calendar.md)，按格子的高度能写几条写几条（至少一条），放不下的最后一条换成“+2”；点标题打开主窗口和这个事项的详情，点“+2”在主窗口的日历里打开那天，点格子的其他地方选中那天，快速添加加到这天；下面没有列表。默认大小正好放下 6 周，窗口拉得很矮时上下滚动。“一周”和“时间轴”是手机上[日历](ui/calendar.md)的周视图和时间轴：上面一行“2026年11月”和换周的 ‹ ›，不在本周时多一个“今天”，触屏上左右滑动也换周；时间轴左边 32 写钟点，一格里几项合成“3 项”。视图在小窗和每个桌面小组件里分别记，和主窗口日历选的视图互不影响；“在主窗口打开”打开主窗口日历的同一个视图和选中的那天。“接下来”和“日程”勾选完成后停留 0.9 秒再收起；其他视图按各自列表更新。提示条可以撤销。点事项打开主窗口和这个事项的详情，小窗收起。
- 没登录时只写“打开 NextTodo 登录”，点了打开主窗口。
- [隐私锁](design.md#隐私锁)锁定时，小窗里是锁屏，在这里也能解锁。
- 页面：小窗是网页端的第二个窗口（窗口名 `panel`），页面按窗口名显示小窗的界面。它和浏览器里多开的标签页一样，与主窗口共用本机的数据和待发队列，自己连同步（见[网页端](web.md#数据)）；[本机模式](local.md#令牌和端口)下两个窗口共用一个会话。提醒的交接、检查更新、[更新日志](design/updates.md#更新日志)弹窗和本机配置的 [AI 整理](ai.md)只在主窗口做，免得做两遍。主窗口每次登录（包括本机模式重新签发会话），小窗都重新加载，读到新的服务器和会话，不管它当时是没登录、还在加载还是停在已经失效的会话里。
- 窗口：App 启动时由 Rust 隐藏着创建好，弹出时不用等页面加载。没有边框、不能调大小，不在任务栏里，在每个桌面空间都能弹出，浮在其他窗口上面。macOS 上窗口在圆角外透明，圆角由页面画（要开 `macOSPrivateApi`）；Windows 11 自动给有阴影的无边框窗口加圆角。
- 摆放：取图标的位置（快捷键打开时也是）和它所在屏幕的工作区；图标在屏幕上半部分就放在它下面，否则放在它上面，和图标水平居中，超出工作区就贴边。图标不在屏幕上时（比如菜单栏放不下被藏起来）留在上次的位置。
- 开关：弹出后聚焦，并通知页面（`shown` 事件），页面聚焦快速添加栏。失去焦点就隐藏；Windows 上点托盘图标会先让小窗失去焦点，所以因此隐藏后 0.5 秒内的那次点击不再弹出。按 Esc 时页面让原生收起小窗（`hide_panel`），和再点图标、再按快捷键一样。macOS 上，小窗从隐藏到打开时记下前台的 App（已经开着时从菜单再打开不算）；是别的 App 的，收起时激活它，小窗随之失去焦点隐藏，那个 App 已经退出或激活不了的，直接隐藏。直接隐藏的话本 App 还在前台，系统会把主窗口提到最前接过焦点，哪怕它原本压在别的窗口下面。只让本 App 退到后台（`NSApplication.deactivate`）不行：它是异步的，小窗隐藏时 App 往往还在前台。打开主窗口用 `open_main` 命令，主窗口得到焦点，小窗随之隐藏；点事项时交给主窗口的是 `<小窗的页面>?open=<事项>`，主窗口在这个页面上打开详情。

## 桌面小组件

一直摆在桌面上的“接下来”、日历或文件夹，不用点图标就看得到，也能勾选完成和快速添加。可以放好几个，各看各的，比如一个“接下来”、一个“月历”。Windows 和 macOS 都有，默认一个也没有。

- 添加和移除：设置“小组件”一类（桌面 App 上也有这一类）最上面一组“桌面上的小组件”，一行一个已经放着的，写它的视图（“接下来”“月历”“毕业论文”），右边是移除按钮；最后一行“添加小组件”，点了弹出菜单选放哪个：“接下来”“日程”“一周”“月历”“时间轴”（关掉时间轴视图时没有），放在主屏幕右上角，已经有的话往左下错开 24，免得正好叠住。小组件视图切换的菜单最后也有“移除这个小组件”。最多 6 个，放满了“添加小组件”不可用。App 启动时（包括登录时启动）放着的都显示。升级前放的一个小组件会保留位置、大小和视图；之前未放的不会自动添加。
- 内容同[菜单栏小窗](#菜单栏小窗)：顶上一行的视图切换（选择和小窗各记各的）和“在主窗口打开”、快速添加栏、列表、勾选和撤销；点事项打开主窗口的详情；隐私锁锁定时是锁屏。它不收起，Esc 只退出批量选择。
- 外观用 Android 小组件的那几项设置（[小组件的设置](android/widgets.md#小组件的设置)）：预览、背景颜色、不透明度、文字颜色，含义和配色一样，存在这台电脑上，改了小组件立即跟着变；桌面上不透明度默认 70%，透出壁纸。文字大小是整个小组件的缩放，同[界面大小](#界面大小)，小、标准、大是正文 13、14、16，默认标准。标题栏开关和“一周”的日子只有 Android 有。背景颜色的第一项在这里叫“跟随主题”：小组件跟着 App 的主题，不是系统的。颜色换的是小组件本身（顶上一行、列表、快速添加栏、批量操作栏、锁屏，锁屏的输入框边线深一档），弹出的菜单和对话框照常跟着主题；正在滑动的那一行用配色里不透明的底色，免得透出下面的操作。窗口本身透明，底色和圆角由页面画，不用系统的 Mica 和亚克力：小组件几乎一直是不活动的窗口，Mica 在不活动时换成纯色。
- 位置和大小：每个小组件各记各的。新放的宽 340、高 440，位置见上；拖顶上一行的空白处移动，拖边缘和角改大小，最小 280×240。位置和大小记在这台电脑上，下次照旧；那块屏幕不在了或者改了缩放，就回到主屏幕的右上角，比主屏幕的工作区大的缩到放得下。
- 层级：在所有窗口下面、桌面图标上面；点它、在里面打字，它也不会盖到别的窗口上面。不在任务栏和 Alt+Tab 里，macOS 的 ⌘` 也跳过它；调度中心里不跟别的窗口一起排开，留在原处；每个桌面空间都有。“显示桌面”以后还在：Windows 的 Win+D、任务栏最右端、Win+M，macOS 的显示桌面（手势、触发角、F11）。
- 页面：每个小组件一个窗口（窗口名 `widget-1`、`widget-2`…，编号不重用），和小窗一样共用本机的数据、自己连同步，主窗口登录时重新加载。小窗和小组件只认主窗口的登录，互不触发重新加载：两个窗口都在没有保存的副本时登录一次，又都听这个广播重新加载的话，会每几百毫秒互相重载一次。移除小组件时，它先等自己的改动在本机存好（没存好就不移除，提示“移除失败：还有改动没有保存，请稍后重试”）再关，主窗口从本机的待发队列里接过它还没被服务端确认的改动（比如离线时勾的），不等下次启动才发。
- Windows：创建时把小组件的所有者设成桌面窗口（Progman，`owner_raw`），仍然 `always_on_bottom`。被拥有的窗口总在所有者上面，Progman 在最底层，所以小组件在别的窗口下面；“显示桌面”把 Progman 提到最上面时，小组件跟着上去。
  - Windows 11 25H2 上实测：只有 `always_on_bottom` 时，Win+D 后小组件被压在 Progman 下面；设了所有者，Win+D、Win+M、点别的窗口、显示桌面时点它，小组件都在，内容照常画。
  - Explorer 重启后桌面窗口换了一个，小组件的所有者随之没了（25H2 上实测窗口还在）：每 10 秒看一次桌面窗口换没换，换了就把小组件交给新的（`SetWindowLongPtrW` 的 `GWLP_HWNDPARENT`，同 `owner_raw` 在创建时做的）。
  - 位置按像素放回原处：tao 把逻辑坐标交给第一块按它的缩放能放下这个点的屏幕，各屏缩放不同时可能是另一块，跨屏挪动时也可能留着原来的像素大小，所以建好以后再按记下的缩放把位置和大小换成像素设一次（窗口透明，页面画出来以前看不见，不会跳一下）。
  - 不用 Rainmeter 的做法（隐藏的辅助窗口、定时检查加前台切换的钩子，发现显示桌面就把小组件临时提到最上层）：它要跟着 Windows 改，24H2 换了桌面窗口的结构时就改过一次；我们只要待在桌面上这一种层级，所有者就够了。也不用 `tauri-plugin-desktop-underlay`：嵌到图标下面的窗口点不了。
  - 取桌面窗口（`GetShellWindow`）和换所有者（`SetWindowLongPtrW`）在 windows crate 里都是 `unsafe`。外壳只在这两个各一行的函数上例外：lint 从 `forbid` 改成 `deny`，这两个函数写明原因放开。
- macOS：层级在普通窗口下面（`always_on_bottom`），再加上 stationary、can join all spaces、ignores cycle 三个 collection behavior（同 Übersicht 能点的组件），显示桌面和调度中心里都不动。NSWindow 从 `NSApplication` 的窗口列表里按 `ns_window()` 的地址找出来，不用 `unsafe`。

## 界面大小

小窗按手机的尺寸画（正文 16，事项行最低 56），放在 360×480 的小窗里显得大，一屏只有五项左右；主窗口有人也想调大调小。所以设置“外观”里有一组“界面大小”，两行各管一个窗口，互不影响：

| 行 | 小 | 标准 | 大 |
|---|---|---|---|
| 主窗口 | 正文 14（0.875 倍） | 正文 16（1 倍，默认） | 正文 18（1.125 倍） |
| 菜单栏小窗（Windows 上叫“托盘小窗”） | 正文 13（0.8125 倍） | 正文 14（0.875 倍，默认） | 正文 16（1 倍） |

- 每行左边是名称，右边是小的分段控件（小、标准、大）。只在桌面 App 里显示：浏览器里用浏览器自己的缩放，手机跟着系统的字体大小。
- 整个窗口按比例缩放：字、图标、间距、行高一起变，用 WebView 原生的页面缩放（`set_zoom`：macOS 的 `pageZoom`，Windows WebView2 的 `ZoomFactor`），和浏览器的 ⌘+ ⌘− 一样，坐标和布局都按缩放后的算，不另写一套尺寸。主窗口变小后页面变宽，按页面宽度切换的布局随之切换，同浏览器缩放。macOS 窗口左上角的三个按钮是系统画的，不跟着缩放；页面上和它们对齐的地方（中栏顶部按钮的中线、左栏收起时让出的宽度、窄窗口的顶栏）按窗口的点来算（CSS 变量 `--zoom`），缩放后仍然对齐、不重叠。
- 窗口本身的大小不变：小窗还是 360×480，内容变小，一屏多放几项（标准约 6 项，小约 7 项）。
- 选择存在本机（和主题一样），每个窗口的页面打开时按自己那一行缩放；在设置里改了，两个窗口都立即生效。

## 小窗快捷键

默认不设：顺手的组合键多半已被系统或别的应用占用（比如 macOS 上 ⌃⌥Space 是切换输入法），由用户自己选。

- 在设置“系统”的“小窗快捷键”一行：右边的框里是当前的快捷键，没设时写“未设置”；设了的框后面有 ×，点了清除。
- 点框开始录制，框里写“请按下快捷键”，按住的修饰键随按随显示。按下带 ⌘、⌃ 或 ⌥（Windows 是 Ctrl、Alt 或 Win）的组合就设好了，马上生效；只带 ⇧ 或不带修饰键的不算，提示要带上哪几个键，接着录制。按 Esc、点别处或切到别的应用取消。
- 录制时先停用当前的快捷键，免得按下同一个组合弹出小窗；取消后恢复。
- 系统不让注册时提示“这个快捷键用不了”，接着录制，可以换一个，原来的设置不变。Windows 上已被别的应用占用的组合注册不上；macOS 不查这种冲突，别的应用用着的组合也能注册上，要用户自己避开。被系统先拦下的组合（比如 macOS 的 ⌘Space）App 收不到，按了没有反应。
- App 启动时注册不上的，那一行写“没有生效，可能已被别的应用占用”。
- `shortcut` 文件读不出来（比如被改坏了）时提示读取失败，那一行按“未设置”显示，录一个新的就覆盖它。
- 写法：macOS 用符号，按 ⌃⌥⇧⌘ 的顺序，如“⌃⌥K”；Windows 写成“Ctrl+Alt+Shift+Win+K”。按键按位置认（`KeyboardEvent.code`），不随输入法和键盘布局变。
- 只存在这台电脑上：App 配置目录里的 `shortcut` 文件，内容如 `control+alt+KeyK`，没设时没有这个文件。Rust 在 App 启动时读它并注册，不等页面，开机启动时也能用。页面经 `shortcut`、`set_shortcut`、`pause_shortcut`（录制时停用和恢复）三个命令读写。

## 提醒

只在 App 运行时提醒（关掉窗口也算运行）：

- 会话开始时和本地副本变化后（第一次变化后 2 秒内交接一次，合并这期间的变化），按和 Android 相同的规则算出将来的所有提醒，整份交给 Rust（`set_reminders` 命令）。
- Rust 用一个线程等到最近的提醒时间，弹出系统通知；列表换了就重新等。等待的计时在电脑睡眠时停走，所以最长 30 秒看一次钟。每次交接还带上上次交接以来到点、事项仍然需要的提醒。Rust 记着线程上次看钟的时间：在它之前到点的已经处理过（该弹的弹了），丢掉；之后、现在之前到点的，只保留上一份列表里就排着的（同一事项、同一时刻；时钟往回调了的，以当前时间为准）。所以电脑刚睡醒时到点的照样弹一次，内容是最新的；期间完成、删除或改期了的不弹；刚在 App 里设的、改过的，时间已经过了的也不弹，和 Android 一样。
- [每日汇总](design/dates.md#提醒)也在这份列表里，没有事项 ID：点它或它的“打开”打开主窗口的“接下来”。电脑睡了几天醒来时，只补弹最近一天的。
- 隐私锁锁定时，交接的提醒和每日汇总只写“有事项提醒”，同[隐藏通知内容](design/dates.md#提醒)；锁定和解锁时立即重新交接，不等 2 秒。点开照常打开主窗口，先显示锁屏，解锁后是这个事项。
- 退出登录时清空提醒（`clear_reminders`），已经到点、还没弹出的也清掉。
- 点提醒或提醒上的“打开”按钮，打开主窗口和这个事项，和 Android 一样（在设置页的先回到“接下来”）。macOS 的通知只有带按钮时才会等用户点击并报告，所以提醒都带这个按钮；通知插件为此每条通知开一个线程，等到用户处理它，提醒一天没几条，可以接受。

## 附件

- 打开[附件](design/attachments.md)：页面把文件交给 Rust 命令 `open_attachment`，请求体就是文件（不转成 JSON），名称放在请求头里（URL 编码）。Rust 把它写进临时目录的 `NextTodo/attachments/<附件 ID>/<名称>`，再用系统默认的应用打开。名称按各系统都能用的规则改成文件名：`<>:"|?*` 换成 `_`，去掉结尾的点和空格，`CON`、`NUL` 这类保留名前面加 `_`，剩下的是空的就叫“附件”，超过 255 字节时截短、保留扩展名。三处用 core 里的同一个函数：桌面、命令行的 `download` 直接调用，Android 经 JNI（`LocalServer.fileName`）。这些文件在 App 启动时删掉。
- 保存：`save_attachment` 同样收到文件，弹出系统的保存窗口，默认文件名是这样改过的附件名称。
- 拖进来：主窗口和小窗关掉 Tauri 自己的拖放处理（`dragDropEnabled: false`），文件拖进窗口时页面收到 HTML 的拖放事件，和浏览器里一样。

## 更新

总体见[总体设计](design/updates.md)。用 `tauri-plugin-updater`：

- 版本 `0.1.<提交数>`，由 `deploy/build.sh` 打包时写入。`tauri build` 同时生成更新包和它的签名（`createUpdaterArtifacts`）：macOS 是 `NextTodo.app.tar.gz`（Intel 版的改名为 `NextTodo-x64.app.tar.gz`），Windows 直接用安装程序。构建脚本据此写出 `/app/desktop.json`，其中的下载地址是相对这个文件的路径，所以同一个镜像部署在哪个域名下都能用。
- 启动时和之后每 6 小时，Rust 取 `<登录的服务器>/app/desktop.json`，把下载地址换成完整地址，交给更新插件判断版本、下载并校验签名。签名里记着版本号，必须和文件里写的一致。
- 下载好以后，macOS 当场替换 App，下次启动生效；Windows 的安装程序一运行就会关掉 App，所以先留在内存里，等点了“重启”再安装（被动模式，只显示进度条），装完自动打开。提示条显示“新版本已准备好，重启后生效”，附“重启”；macOS 不点的话，下次退出再打开时生效，Windows 不点的话，退出后这次的下载作废，下次启动重新检查。
- 更新密钥：私钥文件路径和密码从环境变量 `TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 读取，不进仓库；公钥写在 `tauri.conf.json`。私钥丢了，已装的 App 就收不到更新，只能手动装一次换了公钥的新版本。
- App 装在哪就在哪替换。
- 开发版（`tauri dev`）不检查更新：它直接从构建目录运行，不在 `.app` 里，装更新会把正式版装到构建目录上。

设置页“关于”显示 App 版本，点按它立即检查更新，见[总体设计](design/updates.md)。

## 命令行

安装包里带着同一版本的命令行 `nexttodo`（用法见 [agent 接入](agent.md#命令行)）。设置里令牌下面有“命令行”一组：没装时点“安装”，装好后显示“已安装”，在终端里直接运行 `nexttodo`。App 更新后命令行也随之更新。

| | macOS | Windows |
|---|---|---|
| 在安装包里 | `NextTodo.app/Contents/MacOS/nexttodo`（Tauri 的 `externalBin`） | 安装目录下的 `bin\nexttodo.exe`（`resources`）。单独一个目录，加进 PATH 的只有它 |
| 安装 | 在 `/usr/local/bin` 建指向它的符号链接；没有写权限时，由系统弹窗要管理员密码 | 把 `bin` 目录加到当前用户的 PATH 最前面 |
| 已安装 | 链接存在，并指向这个 App 里的命令行 | 当前用户的 PATH 里有这个目录 |
| App 更新后 | 链接指向的文件随 App 一起换成新版本 | 安装程序先把旧文件改名，再写入新文件 |

- macOS：
  - 从浏览器下载的 App 带隔离属性，安装时不去掉它。打开过的 App 受系统的“App 管理”保护，只有用户在“隐私与安全性 → App 管理”里允许过的程序才能修改；App 自己不在其中，用管理员身份运行也不行（macOS 27 上实测，`xattr` 被内核拒绝）。
  - 从终端运行带隔离属性的 App 里的命令行时，Gatekeeper 按整个 App 检查（日志里是 App 的 bundle ID）：没打开过的 App 会弹出无法验证开发者的对话框并拦下它。用户点过“仍要打开”的 App，命令行随它一起放行：macOS 27 上用带浏览器下载隔离属性的副本实测，直接运行和经符号链接运行都不弹窗。
  - 直接从下载的磁盘映像或“下载”文件夹打开时，系统把 App 放在随机的只读路径里运行（App Translocation），链接会失效。这时提示“请先把 NextTodo 移到“应用程序”文件夹”。
  - shell 的 PATH 由用户自己的配置决定，别的目录里的 `nexttodo`（比如 `cargo install` 装的）可能排在前面。App 管不到这一点，[教程](https://juniexd.github.io/NextTodo/guide/agent#cli)里教用户用 `which -a nexttodo` 检查。
  - `/usr/local/bin/nexttodo` 已经是别的文件，或指向别处的链接（比如自己装的命令行，或移动位置前的这个 App）时，显示“已有另一个 nexttodo”，按钮是“替换”，确认后才覆盖。
- Windows：
  - PATH 由 PowerShell 写入：读出注册表里的原值（不展开 `%变量%`），把目录加在最前面，排在用户以别的方式装的命令行之前，再按 `REG_EXPAND_SZ` 写回，再像系统设置那样向所有窗口广播 `WM_SETTINGCHANGE`，之后新打开的终端就能用。外壳禁止 `unsafe`，所以由 PowerShell 调用这个 Win32 API。脚本用 `-EncodedCommand` 传入，不受命令行引号转义的影响；出错即停，报告失败。
  - 运行中的 `nexttodo mcp` 会占住命令行文件，安装程序不能覆盖它，但可以改名。安装程序的钩子（`src-tauri/windows/hooks.nsh`）在写入前先删旧文件，删不掉（正被占用）就改成临时文件名，并删掉以前留下的、已经没有程序占用的旧文件。
  - 系统的 PATH 排在用户的前面，那里有别的 `nexttodo` 时仍会先用它。往系统 PATH 里放命令行要管理员手动操作，很少见，App 不去解析完整的 PATH，[教程](https://juniexd.github.io/NextTodo/guide/agent#cli)里教用户用 `where.exe nexttodo` 检查。
  - 卸载 App 时不改 PATH，留下的目录已不存在，不影响使用。

## 开机自启

设置“系统”里的“登录时启动”开关，用 `tauri-plugin-autostart`（macOS 写 LaunchAgent，Windows 写注册表的启动项），读写失败时提示。开机启动时带 `--hidden`，只出现在菜单栏或托盘，不弹窗口；macOS 上也不占 Dock，打开窗口以后才出现在 Dock 里。

## 构建

都在 Mac 上构建，在 `apps/desktop` 下运行。更新包要用更新密钥签名，打包前设好[更新](#更新)里的两个环境变量，没有它们打包会失败。

Tauri 构建前先运行 `apps/desktop/cli.sh`（`beforeBuildCommand`、`beforeDevCommand`），编译目标平台的[命令行](#命令行)，放进 `src-tauri/binaries/`。直接用 `cargo` 编译或检查外壳前，先运行一次 `./cli.sh`。

| 平台 | 命令 | 产物 |
|---|---|---|
| macOS（Apple 芯片） | `pnpm tauri build --bundles app,dmg` | `.app`、`.dmg` 和更新包 |
| macOS（Intel） | `pnpm tauri build --target x86_64-apple-darwin --bundles app,dmg` | `.app`、`.dmg` 和更新包 |
| Windows（x64） | `pnpm tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis` | NSIS 安装程序和它的签名 |

- Intel 版在 Apple 芯片的 Mac 上交叉编译，要 `rustup target add x86_64-apple-darwin`；可以在同一台 Mac 上用 Rosetta 运行它来检查。
- Windows 版用 `cargo-xwin` 交叉编译，要 `rustup target add x86_64-pc-windows-msvc`、`cargo install cargo-xwin`、Homebrew 的 `nsis` 和 `llvm`（`llvm` 的 `bin` 要在 `PATH` 里，里面有 `clang-cl` 和 `llvm-rc`）。第一次构建会下载 Windows SDK，可以用 `XWIN_CACHE_DIR` 指定放在哪里。
- 不做苹果签名和公证，用 ad-hoc 签名（`signingIdentity: "-"`）。本机构建的不带隔离属性，直接能打开；从网上下载的第一次打开会被拦下，要到“系统设置 → 隐私与安全性”里点“仍要打开”。
- Windows 安装程序没有代码签名，第一次运行时 SmartScreen 会提示，点“更多信息 → 仍要运行”。默认装到当前用户目录，不需要管理员权限；系统缺 WebView2 时安装程序会下载。
- 版本号：`deploy/build.sh` 打包时是 `0.1.<提交数>`（见[更新](#更新)）；直接用上面的命令打出的是网页端 `package.json` 的版本（0.1.0），装上后会被服务器上的版本更新掉。

## 测试

提醒时间的计算和 Android 共用，已有 Vitest；交接时保留哪些提醒有 Rust 单元测试，由根目录的 `check.sh` 运行。外壳在本机实际操作验证：登录、同步、关窗口后继续同步、提醒到点弹出、开机自启开关、退出登录后提醒清空、更新。

Windows 版在 Windows 11 虚拟机（ARM 版，x64 模拟运行）里验证过：登录、同步、关窗口后隐藏、托盘图标和菜单、提醒弹出和点击打开、开机自启开关、只运行一个实例、更新。调试时：

- 操作页面：启动前设环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`，在虚拟机里经 CDP（`http://127.0.0.1:9222/json`）连接。
- 查看日志和 panic：正式版没有控制台窗口，从命令行启动 `nexttodo-desktop.exe`，把标准错误重定向到文件。
- 测试更新：用本机的 `http` 服务器就行，更新插件允许 `http` 的更新地址，见[直接用 HTTP](design.md#直接用-http)。
