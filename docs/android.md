# Android

Android App（包括小米澎湃 OS）：Capacitor 外壳加载打包在安装包里的网页端，加上截止提醒和桌面小组件。总体要求见[总体设计](design.md#android包括小米澎湃-os)，网页端见[网页端](web.md)。

## 结构

| 位置 | 内容 |
|---|---|
| `apps/web/capacitor.config.ts` | Capacitor 配置。网页端的代码和依赖只有一份，App 用的插件也装在 `apps/web` |
| `apps/android` | 原生工程（Capacitor 的 `android.path` 指到这里）：外壳、小组件（Kotlin + Jetpack Glance）、给网页调用的小插件 |

网页端用 `Capacitor.isNativePlatform()` 区分自己是在浏览器里还是在 App 里，只有连接服务器的方式和下面几项 App 专有的功能不同，界面完全一样。

## 连接服务器

App 的页面来自 `https://localhost`，和服务器不同源，所以不用 Cookie：

- 登录页多一个“服务器”栏，默认 `https://todo.juniexd.cn`。
- 登录得到的会话令牌和服务器地址存在 Capacitor Preferences（Android 的 SharedPreferences，App 私有）；小组件从同一处读取。App 不参加系统备份（`allowBackup="false"`），令牌不会进云端备份。
- HTTP 请求加 `Authorization: Bearer <令牌>`，经 Capacitor 的原生 HTTP 发出（`CapacitorHttp`），不受跨域限制，服务端不需要 CORS。Capacitor 不给 POST 等写请求转发 `AbortSignal`，所以网页端请求的 20 秒期限在 App 里只对 GET 有效，登录、注销等写请求要等系统的网络超时。
- WebSocket 在 `hello` 里带令牌（见 [API](api.md#同步协议)）。
- 设备名是“NextTodo App · Android”。
- 退出登录时先删令牌，再清小组件、取消所有提醒（包括通知栏里已经弹出的）、删本机数据；服务器地址保留，下次登录不用再填。下次启动发现没有令牌时，先清掉小组件和提醒；有没做完的退出（“正在退出”的记录）就接着删本机数据，否则是登录失效（比如小组件先收到 401 删了令牌），本机数据和待发改动留着，同一账号再登录时补发。退出记录写下后、令牌删掉前被杀掉的，下次启动补完退出时也删令牌、清小组件和提醒。
- 退出时连不上服务器的，令牌照样删掉，服务端的这次登录留着，可以在别的设备的设置里“登录的设备”注销（网页端会在下次打开时补上注销，App 删了令牌就补不了）。
- 登录失效（服务端不再接受令牌）时，和网页端一样保留本机数据和待发改动，同一账号再登录时补发；令牌、小组件和提醒照样清掉。打开 App 时才发现的（本机没有数据，问服务端得到 401）也一样。
- 登录页改了服务器地址时，内存里之前登录留下的令牌作废，不会发给新的服务器。
- 服务端告诉小组件会话已失效（401）时，如果期间没有重新登录，小组件删掉令牌，显示“打开 NextTodo 登录”；已经重新登录的，旧会话的 401 什么也不改。
- 邀请链接用服务器地址（App 里页面的来源是 `https://localhost`）。
- Capacitor 的桥接日志关掉（`loggingBehavior: "none"`），否则调试版会把登录密码和令牌写进 logcat。
- 返回键（含侧滑返回）一次退一步：先关掉对话框、弹窗、详情，再退出文件夹，最后退到后台；底部栏的页面之间不来回，见[界面](ui.md#返回)。

## 截止提醒

用 `@capacitor/local-notifications` 在本机排定提醒，到点由系统弹出，不依赖推送：

- 会话开始时、本地副本变化后（第一次变化后 2 秒内处理一次，合并这期间的变化）和 App 回到前台时，重新计算未完成事项的提醒时间：截止时间减去 `remind_before`。取将来最近的 50 个，和已排定的比较，增删差异。比较时标题、内容、时间和是否精确都要相同；时间和是否精确放在每个提醒的 `extra` 里比较（插件读回的时间是它自己的格式）。普通闹钟可能到点后才送达：已经过了时间、还没送达的提醒，只要事项仍要这个提醒就保留。
- 通知 ID 用事项编号（服务端分配的整数，每个用户唯一）。还没同步、没有编号的事项，同步后再排。
- 提醒排的是具体时刻。改了手机时区，要等 App 下次回到前台才按新时区重排。
- 通知标题是事项标题，内容是截止时间和文件夹；点开进入 App 并打开这个事项（开着的设置面板关掉；小组件里点事项也一样）。
- 更新提醒或小组件失败时，提示条告诉用户，下次变化时再试。
- 精确到点需要“闹钟和提醒”权限（`SCHEDULE_EXACT_ALARM`）。第一次设置提醒时请求通知权限。没有精确闹钟权限时排普通闹钟（系统可能推迟几分钟），不弹系统设置（插件默认每次排提醒都会打开）；设置里提示并给出打开系统设置的按钮，允许后回到 App 时按精确闹钟重排。

## 小组件

Jetpack Glance 写的“接下来”小组件：

- 每项显示标题、文件夹和截止时间（逾期红色、今天琥珀色，规则同网页）；左边的圆圈点一下完成，点事项打开 App 里的详情；点标题回到 App 的首页；右上角 `+` 打开 App 并聚焦快速添加，刷新按钮立即刷新。
- 数据来源：
  - App 每次本地副本变化后，把“接下来”的列表写给小组件（经 `Widget` 插件存入 SharedPreferences 并通知刷新），格式同 `next` 工具的数据，带事项编号。
  - 小组件自己每 15 分钟（WorkManager 周期任务，联网时）和点刷新按钮时，用令牌调用 `POST /tools/next` 取最新列表。
  - 列表按请求的先后编号，只有比已写入的更新才写；取回来时令牌已经换了（退出或换了账号）的也丢掉。
- 勾选完成时直接调用 `POST /mutations`（`task.update`，`done: true`，改动 ID 由小组件生成；已经在别处完成的照样算成功），成功后按列表里的事项编号、照插件的做法取消这个事项的提醒（App 可能没在运行），再刷新；期间重新登录过的不动提醒，因为编号可能已经是另一个账号的。失败时提示并保持原样。
- 没登录时显示“打开 NextTodo 登录”。

## 澎湃 OS

系统会清理后台，小组件的定时刷新和提醒需要 App 被允许“自启动”、省电策略设为“无限制”。App 第一次启动时显示一张说明卡片，按钮打开本 App 的系统设置页；在设置里也能再次查看。

## 构建和签名

- 需要 Android SDK（`ANDROID_HOME`）和 JDK 21（Capacitor 8 的 Gradle 版本还不支持更新的 JDK）。
- `pnpm android:build`（在 `apps/web` 下）：构建网页端、`cap sync android`，再用 Gradle 打 release APK。
- 正式版用自签名的密钥签名，直接安装。密钥库和密码不进仓库：路径和密码从环境变量 `NEXTTODO_KEYSTORE`、`NEXTTODO_KEYSTORE_PASSWORD` 读取。
- `versionCode` 用 git 提交数，`versionName` 用 `package.json` 的版本。

## 测试

- 网页端的逻辑（提醒时间计算、小组件列表）用 Vitest 测。
- 原生部分在模拟器上实际操作验证：登录、同步、离线修改、提醒到点弹出、小组件显示和勾选。
