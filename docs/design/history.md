# 改动记录和撤销

- 每个改动都记录来源：谁改的，在哪台设备上，或用的哪个令牌。
- 每次操作是一个批次，一次批量应用也只算一个批次。自己的令牌做的批次，界面上提示“Claude Code 添加了 12 项”，旁边附撤销按钮；别人的改动见[共享](sharing.md)。命令行和 MCP 用 `log` 查看、`undo <批次>` 撤销。
- 设置里的“改动记录”列出看得到的全部批次（同 `log`，改动日志保留 90 天），新的在前，按天分组，每条写谁、几点、改了什么，可以撤销；已经撤销了的标“已撤销”，不能再撤销：一个改动和撤销它的、撤销这些撤销的连成一串，每次撤销都把这一串翻过来，和最新的一次方向相反的就是已撤销。比如撤销了一次撤销，原来的改动就不再是已撤销；接着又撤销原来的改动，那次撤销的撤销也成了已撤销。一次撤销好几个批次、或者撤销的同时还改了别的（只有直接调 API 才会这样），不连进这一串：它自己没被撤销时，它撤销的那几个算已撤销。按批次判断，不逐项核对：中间另有改动动过其中一部分东西时，可能把还能撤销的标成已撤销。可以只看删除了事项、文件夹或附件的，用来找回误删的东西，所以不另做回收站。本机模式和手机上都有；连服务器时要联网才看得到。
- 撤销会生成一组反向改动，作为新批次写入，本身也能再撤销。只改回那次改动过的字段，之后别的改动保留；截止时间分成日期、时间和按它算的提醒、重复三部分，各自判断；按开始算的提醒、指定时间的提醒也各自判断。撤销新建的文件夹（包括复制出来的）时，那次建的事项和文件夹照常删掉；之后又放进去的东西保留，装着它们的文件夹也保留。那次把一个文件夹删掉、改名或移走，又在原处建了同名的（或用了它的 ID），之后又往新的里放了东西时，旧的回不来，撤销失败，什么也不改，先把那些东西移走再撤销。
- 撤销改了完成次数的批次（重复的事项完成一次，或撤销这样一次），要求它仍是算数的最后一次：把这之后改过这个事项完成次数的批次按先后过一遍，正好把还算数的最后一次改回去的（撤销），两个都不再算数，其余的算数；过完只剩它，而且事项现在的次数和它改成的一样，才能撤销。所以完成两次以后可以从近到远一次次撤销；之后又完成过的（比如离线的设备撤销时，别的设备已经又完成了一次），或者撤销后同一天又完成、次数和日期都和原来一样的，改回次数会把那些一起抹掉，拒绝并提示“在这之后又完成或撤销过，请先撤销后来的那次”。同一批里排在撤销前面的操作也算。一个批次完成同一事项不止一次的（比如一次补记两天），撤销时从最后一次往前逐次判断，批次里排在后面的那几次也算在“这之后”，所以整批能一起撤销。服务端查这个批次之后的记录，页面查它知道的；两边按 `fixtures/undo-done.json` 校验。
